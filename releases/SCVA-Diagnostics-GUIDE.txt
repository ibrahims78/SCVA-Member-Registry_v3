  الفصل الأول — ما هي هذه الأداة وما الهدف منها؟
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

SCVA-Diagnostics.bat هو ملف تشخيص شامل مكتوب بلغة Windows Batch
Script. الهدف منه اكتشاف أي مشكلة تمنع تطبيق "SCVA Members" من
العمل بشكل صحيح — وتحديداً مشاكل قاعدة البيانات وعدم ظهور
البيانات عند إعادة التشغيل.

تكمن أهميته في:

  ✦ يعمل بدون تثبيت أي برنامج إضافي
  ✦ لا يُعدّل أي ملف أو إعداد (يقرأ فقط، لا يكتب إلا ملف تقرير)
  ✦ يُنتج تقرير نصي كاملاً يمكن إرساله لفريق الدعم
  ✦ يعطي نتائج واضحة: [PASS] [WARN] [FAIL]
  ✦ يُقدّم الحلول فوراً عند اكتشاف أي مشكلة

خطوة 1: الموقع الصحيح للملف
──────────────────────────────
ضع ملف SCVA-Diagnostics.bat داخل مجلد التطبيق مباشرة:

  ✦ الصحيح:   C:\SCVA Members_win\SCVA-Diagnostics.bat
  ✗ الخطأ:    C:\SCVA-Diagnostics.bat   ← مجلد مختلف لا يعمل

السبب: الملف يحدد مجلد التطبيق تلقائياً من موقعه الخاص (%~dp0)،
فإذا كان في مجلد مختلف لن يجد SCVA Members.exe ولا ملفات resources.


خطوة 2: تشغيل الملف
──────────────────────
انقر بزر الماوس الأيمن على الملف ← "تشغيل كمسؤول" (Run as administrator)

لماذا كمسؤول؟ لأن بعض الفحوصات تحتاج صلاحيات مرتفعة:
  - قراءة إعدادات Windows Defender
  - فحص قائمة العمليات النشطة
  - فحص المنافذ الشبكية (netstat)
  - اختبار الكتابة وإعادة التسمية


خطوة 3: اختيار وضع التشخيص
──────────────────────────────
عند التشغيل يطلب الملف اختيار أحد ثلاثة أوضاع:

  ┌─────────────────────────────────────────────────────────┐
  │  [1] فحوصات ما قبل التشغيل (Pre-launch)                │
  │      شغّله قبل فتح تطبيق SCVA                          │
  │      يفحص: النظام، ملفات التطبيق، قاعدة البيانات،      │
  │      الصلاحيات، Windows Defender                        │
  │                                                         │
  │  [2] فحوصات ما بعد التشغيل (Post-launch)               │
  │      شغّله بعد فتح تطبيق SCVA وتسجيل الدخول            │
  │      يفحص: العمليات، الخادم المحلي، API، استمرارية     │
  │      البيانات عند الإغلاق                               │
  │                                                         │
  │  [3] التشخيص الكامل ← الموصى به دائماً                 │
  │      يجمع الوضعين 1 و 2 معاً بالتسلسل                  │
  └─────────────────────────────────────────────────────────┘

  الفصل الثالث — المتغيرات والمسارات التي يعمل بها الملف
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

يُعرّف الملف عند بدئه هذه المتغيرات تلقائياً:

  APP_DIR   = المجلد الذي يوجد فيه هذا الملف .bat
              مثال: C:\SCVA Members_win

  APP_EXE   = مسار ملف التطبيق التنفيذي
              مثال: C:\SCVA Members_win\SCVA Members.exe

  DATA_DIR  = مجلد البيانات (منذ v1.5.0 = نفس مجلد التطبيق)
              مثال: C:\SCVA Members_win
              ملاحظة: في الإصدارات القديمة (قبل v1.5.0) كان:
              C:\Users\admin\AppData\Roaming\SCVA Members

  DB_FILE   = ملف قاعدة البيانات SQLite
              مثال: C:\SCVA Members_win\scva-members.db

  DB_TMP    = ملف قاعدة البيانات المؤقت (يُستخدم أثناء الحفظ)
              مثال: C:\SCVA Members_win\scva-members.db.tmp

  WASM      = ملف محرك قاعدة البيانات (WebAssembly)
              مثال: C:\SCVA Members_win\resources\app.asar.unpacked\
                    node_modules\sql.js\dist\sql-wasm.wasm

  APP_PORT  = منفذ الخادم المحلي: 43210 (ثابت)

  REPORT    = ملف التقرير الناتج
              مثال: C:\SCVA Members_win\SCVA-Diagnostics-Report.txt

════════════════════════════════════════════════════════════════
  المرحلة 1 — نظام التشغيل والمعدات (Operating System & Hardware)
════════════════════════════════════════════════════════════════

هذه المرحلة تتحقق من أن البيئة تستوفي الحد الأدنى لتشغيل التطبيق.

┌─ الفحص 1: نسخة Windows (Windows Version) ──────────────────┐
│                                                              │
│  الأمر المستخدم: ver                                        │
│  المتوقع: رقم إصدار رئيسي 10 أو أعلى (Win10/Win11)         │
│                                                              │
│  [PASS] major version 10 ← Windows 10 أو 11                │
│  [FAIL] major version < 10 ← نظام قديم غير مدعوم           │
└──────────────────────────────────────────────────────────────┘

┌─ الفحص 2: معمارية النظام (Architecture) ───────────────────┐
│                                                              │
│  يقرأ متغير: PROCESSOR_ARCHITECTURE و PROCESSOR_ARCHITEW6432│
│  المتوقع: AMD64 (أي 64-bit)                                 │
│                                                              │
│  [PASS] AMD64 ← 64-bit مؤكد                                │
│  [PASS] WOW64 ← برنامج 32-bit يعمل على نظام 64-bit         │
│  [FAIL] غير ذلك ← نظام 32-bit لا يدعمه التطبيق            │
│                                                              │
│  لماذا مهم؟ تطبيق SCVA مُبنى لـ win32-x64 فقط.            │
└──────────────────────────────────────────────────────────────┘

┌─ الفحص 3: صلاحيات المسؤول (Admin Rights) ─────────────────┐
│                                                              │
│  الأمر المستخدم: net session                                │
│  يُعيد errorlevel=0 فقط عند تشغيل التطبيق كمسؤول          │
│                                                              │
│  [PASS] errorlevel=0 ← يعمل كمسؤول                        │
│  [WARN] errorlevel≠0 ← ليس مسؤولاً، بعض الفحوصات قد تفشل │
│                                                              │
│  ملاحظة: هذا تحذير وليس خطأ — التطبيق نفسه لا يشترط       │
│  صلاحيات المسؤول للتشغيل، لكن أداة التشخيص قد تُعطي        │
│  نتائج غير دقيقة بدونها.                                   │
└──────────────────────────────────────────────────────────────┘

┌─ الفحص 4: الذاكرة العشوائية (RAM) ────────────────────────┐
│                                                              │
│  الأمر المستخدم: PowerShell                                 │
│    [Math]::Round((Get-CimInstance Win32_OperatingSystem)     │
│    .TotalVisibleMemorySize/1024)                             │
│  النتيجة بالميغابايت تُكتب في ملف مؤقت ثم تُقرأ.           │
│                                                              │
│  [PASS] >= 4096 MB ← يفوق الحد الأدنى                     │
│  [WARN] < 4096 MB و > 0 ← أقل من المستحسن                 │
│  [WARN] = 0 ← فشل في قراءة الذاكرة                        │
│                                                              │
│  لماذا ملف مؤقت؟ طريقة backtick في Batch غير موثوقة        │
│  على بعض إصدارات Windows، لذا يكتب PowerShell النتيجة     │
│  في %TEMP%\scva_mem.tmp ثم يقرأها Batch منه.               │
└──────────────────────────────────────────────────────────────┘

┌─ الفحص 5: مساحة القرص (Disk Space) ───────────────────────┐
│                                                              │
│  الأمر المستخدم: PowerShell                                 │
│    [Math]::Round((Get-PSDrive C).Free/1MB)                  │
│  يقيس المساحة الخالية على محرك C: بالميغابايت.             │
│                                                              │
│  [PASS] >= 500 MB ← كافٍ                                   │
│  [FAIL] < 500 MB و > 0 ← غير كافٍ                         │
│  [WARN] = 0 ← فشل في القراءة                              │
└──────────────────────────────────────────────────────────────┘

  المرحلة 2 — ملفات التطبيق (Application Files)

┌─ الفحص 1: الملف التنفيذي (App EXE) ───────────────────────┐
│                                                              │
│  يبحث عن: SCVA Members.exe في APP_DIR                      │
│                                                              │
│  [PASS] موجود ← يعرض حجمه بالبايت                         │
│  [FAIL] غير موجود ← الملف .bat ليس في مجلد التطبيق        │

┌─ الفحص 2: موارد التطبيق (App Resources) ──────────────────┐

│  يبحث عن: resources\app.asar                               │
│  هذا الأرشيف هو الكود الكامل للتطبيق (Electron + React)   │
│                                                              │
│  [PASS] موجود ← التطبيق مُثبَّت بشكل صحيح                 │

┌─ الفحص 3: ملف WASM — محرك قاعدة البيانات ─────────────────┐
│                                                              │
│  هذا أهم فحص في المرحلة الثانية بالكامل.                   │
│                                                              │
│  يبحث عن:                                                   │
│    resources\app.asar.unpacked\node_modules\                 │
│    sql.js\dist\sql-wasm.wasm                                 │
│                                                              │
│  ما هو هذا الملف؟                                           │
│  sql-wasm.wasm هو ملف WebAssembly يحتوي على محرك SQLite     │
│  المُترجَم. التطبيق يُحمّله في الذاكرة ليتمكن من فتح       │
│  قاعدة البيانات وقراءتها وكتابتها. بدونه لا تعمل           │
│  قاعدة البيانات إطلاقاً.                                    │
│                                                              │
│  لماذا يجب أن يكون خارج app.asar؟                           │
│  ملفات WebAssembly لا يمكن تنفيذها من داخل أرشيف .asar    │
│  (وهو نظام ملفات افتراضي). يجب أن تكون على القرص الفعلي   │
│  ليتمكن النظام من تحميلها.                                 │
│                                                              │
│  [PASS] موجود ← يعرض حجمه (~644 KB)                        │
│  [FAIL] غير موجود ← كارثة! سلسلة الفشل:                   │
│          WASM مفقود → محرك DB يفشل → API تُعيد أخطاء →    │
│          لا يُكتب ملف .db → كل البيانات تضيع عند الإغلاق   │
│                                                              │
│  هذه المشكلة تم إصلاحها نهائياً في الإصدار 1.3.0.          │
└──────────────────────────────────────────────────────────────┘

════════════════════════════════════════════════════════════════
  المرحلة 4 — صلاحيات الكتابة واختبار إعادة التسمية
════════════════════════════════════════════════════════════════

هذه أهم مرحلة لتشخيص مشاكل حفظ البيانات.

┌─ الفحص 1: صلاحية الكتابة (Write Access) ──────────────────┐
│                                                              │
│  ينشئ ملف مؤقت في مجلد البيانات ثم يحذفه فوراً.           │
│                                                              │
│  [PASS] كتب وحذف بنجاح ← صلاحيات الكتابة مؤكدة           │
│  [FAIL] لم يُنشأ الملف ← مجلد التطبيق محمي ضد الكتابة    │
│          الحل: انقل مجلد التطبيق خارج Program Files        │
└──────────────────────────────────────────────────────────────┘

┌─ الفحص 2: اختبار إعادة التسمية الذرية (Atomic Rename) ────┐
│                                                              │
│  يُحاكي بالضبط ما يفعله التطبيق عند الحفظ:                │
│    1. ينشئ ملف: diag-test.tmp                              │
│    2. يُحاول إعادة تسميته إلى: diag-test.db                │
│    3. يتحقق من وجود diag-test.db                           │
│    4. يحذف ملفات الاختبار                                  │
│                                                              │
│  [PASS] نجح ← الحفظ الذري سيعمل                           │
│  [WARN] فشل إعادة التسمية لكن الكتابة المباشرة تعمل       │
│          ← مكافحة الفيروسات تحجب rename لكن التطبيق        │
│             يتجاوزها بالكتابة المباشرة (v1.2.0+)            │
│          ← هذا [WARN] وليس [FAIL] — البيانات ستُحفظ        │
│  [FAIL] كلاهما فشل ← مشكلة صلاحيات حرجة                  │
└──────────────────────────────────────────────────────────────┘

┌─ الفحص 3: قفل ملف قاعدة البيانات (DB File Lock) ──────────┐
│                                                              │
│  يتحقق إذا كان .db مقفولاً من برنامج آخر (مكافحة فيروسات)│
│                                                              │
│  [PASS] غير مقفول ← الحفظ سيعمل بدون عوائق               │
│  [WARN] مقفول ← مكافحة الفيروسات تفحصه حالياً            │
│          الحل: أضف مجلد التطبيق كاستثناء في مكافحة الفيروسات│
└──────────────────────────────────────────────────────────────┘

    // قبل:

ج: الخادم يعمل بشكل مثالي لكن الجلسة غير مفتوحة.
   هذا سلوك طبيعي وصحيح قبل تسجيل الدخول.

س: هل التطبيق يعمل من USB بدون تثبيت؟
ج: نعم، ابتداءً من الإصدار 1.5.0. قاعدة البيانات تُحفظ
   في مجلد التطبيق. انقل المجلد كاملاً إلى USB والتطبيق
   سيعمل على أي جهاز Windows 10/11 (64-bit) بدون تثبيت
   أي برامج إضافية. ملاحظة: Electron ينشئ مجلد AppData
   للاستخدام الداخلي لكن لا يحتوي على بياناتك.

س: لماذا تستخدم PowerShell داخل ملف .bat؟
ج: لأن Batch Script لا يملك أوامر مباشرة للوصول إلى:
   - WMI (معلومات الذاكرة والمعالج)
   - Windows Defender API
   - اختبار قفل الملفات
   PowerShell يوفر هذه القدرات ويعمل على كل Windows 10/11.
