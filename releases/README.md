## 🔍 التحقق من اتصال قاعدة البيانات (موجه الأوامر CMD)

إذا كانت البيانات تختفي بعد إعادة التشغيل، شغّل هذه الأوامر في **موجه الأوامر (CMD)** للتشخيص:

### 1. التحقق من وجود ملف قاعدة البيانات وحجمه
```cmd
dir "%APPDATA%\SCVA Members\scva-members.db"
```
**النتيجة المتوقعة:** يجب أن يظهر الملف بحجم > 0 بايت بعد إضافة بيانات.  
**إذا كان الحجم 0 أو الملف غير موجود** ← المشكلة في الحفظ.

### 2. التحقق من محتويات المجلد كاملاً
```cmd
dir "%APPDATA%\SCVA Members\"
```
- إذا وجدت ملف `scva-members.db.tmp` ← يعني إعادة التسمية كانت تفشل (المشكلة المُصلَّحة في v1.2.0)
- يجب وجود `scva-members.db` فقط

### 3. التحقق من صلاحيات الكتابة على المجلد
```cmd
icacls "%APPDATA%\SCVA Members"
```
**النتيجة المتوقعة:** يجب أن يظهر اسم المستخدم الحالي مع `(F)` أو `(M)` (Full Control / Modify).  
إذا لم تجد صلاحيات الكتابة، شغّل التطبيق كـ **مسؤول (Run as Administrator)**.

### 4. إنشاء المجلد يدوياً إذا لم يكن موجوداً
```cmd
mkdir "%APPDATA%\SCVA Members"
```

### 5. التحقق من حجم ملف قاعدة البيانات (بعد إضافة البيانات وقبل الإغلاق)
```cmd
:: شغّل هذا الأمر أثناء تشغيل التطبيق بعد إضافة بيانات
for %f in ("%APPDATA%\SCVA Members\scva-members.db") do echo الحجم: %~zf بايت
```
**النتيجة المتوقعة:** > 50,000 بايت (50 كيلوبايت) على الأقل إذا يوجد أعضاء.

### 6. اختبار صلاحية الكتابة يدوياً
```cmd
echo test > "%APPDATA%\SCVA Members\write-test.txt" && echo الكتابة تعمل بشكل صحيح && del "%APPDATA%\SCVA Members\write-test.txt"
```

### 7. التحقق من استثناءات Windows Defender
```cmd
powershell -Command "Get-MpPreference | Select-Object -ExpandProperty ExclusionPath"
```
إذا كان المجلد غير مدرج في الاستثناءات وكان Windows Defender يحجب الكتابة، أضفه:
```cmd
powershell -Command "Add-MpPreference -ExclusionPath '%APPDATA%\SCVA Members'"
```

### 8. التحقق من أن التطبيق لا يعمل بنسختين في نفس الوقت
```cmd
tasklist | findstr /i "SCVA"
```
إذا ظهر السطر مرتين → أغلق جميع النسخ وأعد التشغيل.

## 🆕 ما الجديد في الإصدار 1.2.0

### 🐛 إصلاح حرج: اختفاء البيانات بعد إعادة التشغيل

**المشكلة:** على Windows، عملية `fs.renameSync` التي تُستخدم للكتابة الذرية لقاعدة البيانات كانت تفشل بصمت بخطأ `EPERM` في حالات معينة (مثل: فحص Windows Defender للملف، أو وجود مؤشر مفتوح على الملف). النتيجة: يُكتب الملف المؤقت `.tmp` بنجاح لكن الملف الأصلي `.db` لا يُحدَّث أبداً. البيانات تبقى في الذاكرة فقط وتضيع عند الإغلاق.

**الإصلاح:** آلية حفظ ذات 3 مستويات:
1. **المحاولة الأولى:** الكتابة الذرية (temp → rename) — الأفضل للاستقرار
2. **الاحتياط الأول:** إذا فشلت إعادة التسمية → كتابة مباشرة للملف الهدف
3. **الاحتياط الأخير:** إذا فشل كل شيء → كتابة مباشرة بدون ملف مؤقت

### ⚡ تحسين الحفظ التلقائي
- الحفظ التلقائي كل **5 ثوانٍ** (كان 15 ثانية) — يقلّص نافذة فقدان البيانات عند إغلاق التطبيق مفاجئاً

### 🛡️ تحسين معالج الإغلاق
- معالج `before-quit` يبحث عن وحدة قاعدة البيانات بطريقتين (مسار مباشر + فحص كاش `require`) لضمان الحفظ النهائي حتى في حالات مسارات الـ asar الخاصة
- دعم إشارات `SIGTERM` و `SIGINT` لإغلاق نظيف عند إيقاف التطبيق من مدير المهام

## 🐛 حل المشكلات

**التطبيق لا يفتح:**
- تأكد أن نظامك 64-bit (لا يعمل على 32-bit)
- جرّب تشغيل `SCVA Members.exe` كمسؤول (Run as Administrator)
- تأكد من أن مضاد الفيروسات لا يحجب التطبيق

**لا تظهر كلمة المرور الأولية:**
- انظر إلى نافذة الطرفية (cmd) التي تفتح مع التطبيق
- إذا لم تجدها، احذف ملف قاعدة البيانات (أو انقله) وأعد تشغيل التطبيق

**بطء عند أول تشغيل:**
- طبيعي — التطبيق يُهيّئ قاعدة البيانات وخادم الواجهة محلياً

**لا يمكن فتح الملف (خطأ Windows Defender):**
- افتح Windows Security → Virus & Threat Protection
- أضف مجلد التطبيق كاستثناء

**البيانات لا تظهر بعد إعادة التشغيل:**
- **في الإصدار 1.2.0 تم إصلاح هذه المشكلة بشكل جذري**
- للتشخيص: راجع قسم "التحقق من اتصال قاعدة البيانات" أعلاه
- تأكد أن التطبيق يملك صلاحيات الكتابة إلى:  
  `C:\Users\[اسم المستخدم]\AppData\Roaming\SCVA Members\`
